# v171: 답변 단위에서 추천 여정 단위로 검증 확대

## 운영 수정
- AI가 검색 요청으로 판단한 경우에만 명시한 지원 역의 단일 이름을 입력 값으로 검증·보완한다. 여러 위치는 임의 선택하지 않고, 설명·FAQ에 나오는 역 이름으로 검색을 강제하지 않는다.
- 상대 가격 변경의 의미를 budgetRelation으로 받으며 금액 미정이면 예산을 질문한다. 현재 위치 변경은 locationReference=current로 이전 기준점을 먼저 해제하고 실제 기기 좌표를 다시 요구한다.
- 서수 참조 검사는 상세·비교·지도에서만 수행한다. 카드가 없는 서수 요청은 기술 오류 대신 대상 확인으로 되돌린다. 무관한 조건 변경에 잘못 붙은 referencePositions는 실행에 사용하지 않는다.
- '그 조건은 빼줘'처럼 대상 없는 파괴적 변경은 적용하지 않고 확인한다. 명시한 영업 조건 해제는 false/null 표현 차이로 실패하지 않도록 clear 값을 정규화한다.

## 검증 방법
- build-worker 및 policy-smoke. 실제 운영 API 경로에 모의 모델·위치 제공자를 연결하여 반경 답변→카드, 예산 질문→답변→동의→카드, 대상 없음→수동 복구, 현재 위치 실패→역 입력→카드까지 검증한다.
- 별도 QA 폴더에서 실제 서비스에 10개 독립 대화 × 5턴 = 50회 요청한다. 같은 시나리오 안에서는 응답을 다음 발화의 문맥으로 전달한다. 카드명이나 미확인 동의 단계는 실제 응답에 따라 선택한다. 실패한 호출을 숨기거나 재시도하여 성공으로 교체하지 않는다.
- 개별 답변 50개 판정과 전체 여정 10개 판정을 분리한다. 최초 추천에 도달했어도 조건 손실·대상 오류·불필요한 질문 반복·복구 실패가 있으면 해당 여정은 실패다. 0건 안내만 올바르게 말하는 것으로 추천 여정 성공을 인정하지 않는다.
- API 기반 검증은 실제 모바일 화면·기기 GPS·외부 지도 앱 복귀를 검증하지 않는다. 실제 추천 이유/등록 사진의 누락은 기존 실제 데이터 상태 그대로 유지한다. 키 파일은 조회하지 않는다.
