# v123 질문 문구와 답변 UI

## 원칙과 화면

질문은 AI 말풍선의 질문 문장에만 두고, 칩과 버튼에는 사용자가 선택하는 답·행동을 적었어요. `제가 골라드릴까요?`는 종류 질문 문장에만 들어가며 새 칩 라벨·전송 메시지에는 없어요. 오래 저장된 해당 라벨도 화면에서는 `네, 골라주세요`로 바꿔 보여줘요.

- 종류 질문: 안내 → 질문 문장 → 3열 × 2행 타일 → 전체 폭 `네, 골라주세요` 테두리 버튼이에요. `카페·디저트`는 한 타일로 묶었어요. 타일은 최소 52px, 간격 8px, 이름 15px이고 전체 폭 버튼은 최소 48px이에요.
- 지역 질문: `지금 어디세요?` → 검정 `현재 위치 연결` 전체 폭 버튼 → 3열 × 2행 지역 타일 → 전체 폭 `직접 입력` 버튼이에요. 직접 입력은 기존 입력창을 열어 포커스하고 기계 라벨을 전송하지 않아요. 위치 연결은 브라우저 위치 연결 경로를 유지해요.
- 메뉴 후보: 안내 문장 → 메뉴 카드 3개 → 연한 `다른 메뉴 보기`예요. 메뉴 선택은 `국밥 먹을래`처럼 사용자 문장으로 전송해요. 이미 고른 종류와 이전 메뉴 제외 원칙을 유지해요.
- 후속 동행 질문: `누구와 가세요?` → 혼자/2~3명/회식/가족 네 칩이 한 줄에 들어가고, 맨 끝의 연한 `상관없어요`는 공간이 부족하면 다음 줄로 넘어가요. 높이 40px 이상, 간격 8px이고 가로 스크롤을 만들지 않아요.
- v122 카드·칩 이력을 지우지 않고 선택 체크와 진한 테두리, 나머지 비활성을 유지해요. 새 답변은 기존 일반 입력의 분석→정책→렌더 경로로 처리해요. `네, 골라주세요`도 분류 결과가 불확실할 때 흐름을 잃지 않도록 명시적 답으로 처리해요.

## 칩·버튼 라벨 표

고정 답변 라벨은 공백·문장부호를 포함해 2~8자로 검사해요. 실제 메뉴·식당 이름은 데이터 제목이므로 이 길이 검사로 잘라내지 않아요. 물음표와 `제가`, `~드릴`, `~까요` 같은 AI 말투는 서버와 렌더러에서 걸러요.

| 구분 | 화면에 보이는 라벨 | 전송 문장 또는 동작 |
| --- | --- | --- |
| 종류 타일 | 한식 · 중식 · 일식 · 양식 · 분식 | `한식으로 골라줘` 등 |
| 종류 타일 | 카페·디저트 | `카페·디저트로 골라줘` → 기존 카페 메뉴 묶음 |
| AI에게 맡기기 | 네, 골라주세요 | `네, 골라주세요` |
| 지역 주 버튼 | 현재 위치 연결 | `지금 내 주변에서 찾아줘` → 브라우저 위치 연결 |
| 지역 타일 | 강남 · 홍대 · 역삼 · 성수 · 종로 · 여의도 | `강남이에요`, `홍대예요`, `역삼이에요`, `성수예요`, `종로예요`, `여의도예요` |
| 지역 입력 | 직접 입력 | 기존 지역 입력창 열기·포커스 |
| 메뉴 카드 | 국밥 · 제육볶음 · 냉면 등 실제 메뉴명 | `국밥 먹을래` 등 |
| 메뉴 다시 고르기 | 다른 메뉴 보기 | `다른 메뉴 보기` → 같은 종류의 미제안 메뉴 |
| 동행 | 혼자 · 2~3명 · 회식 · 가족 | `혼자 먹을 거예요`, `2~3명이 가요`, `회식이에요`, `가족과 함께 가요` |
| 동행·선택 조건 생략 | 상관없어요 | `상관없어요` → 해당 선택 슬롯 asked 처리. 지역에는 없어요. |
| 메뉴 방향 되묻기 | 고기 · 한식 · 면 요리 · 일식 · 중식 · 분식 · 카페 | 해당 음식을 먹고 싶다는 자연어 문장 |
| 낮은 신뢰도 확인 | 메뉴 고르기 · 식당 찾기 | `오늘 뭐 먹을지 같이 골라줘`, `먹을 곳 찾아줘` |
| 결과 아래 행동 | 다른 곳 보기 · 조건 바꾸기 | `다른 곳도 보여줘` 또는 조건 선택기 열기 |
| 조건 선택 | 지역 바꾸기 · 메뉴 바꾸기 · 상황 추가 | 해당 축 선택기·상황 시트 열기 |
| 소수 결과 지역 대안 | 역삼에서 찾기 · 논현에서 찾기 등 | 지역을 바꾼 검색 문장 |
| 소수 결과 음식 대안 | 설렁탕 먹기 · 곰탕 먹기 등 | 음식을 바꾼 검색 문장 |
| 범위 안내 뒤 시작 | 메뉴 고민하기 · 식당 찾기 | 기존 메뉴·식당 검색 시작 문장 |

8자를 넘던 `다른 곳도 보여줘`는 화면 라벨만 `다른 곳 보기`로 줄였고 실제 전송 문장은 그대로예요. `설렁탕으로 바꾸기` 같은 긴 음식 대안은 `설렁탕 먹기`처럼 줄였어요. 기존 1글자 질문 칩 `면`은 `면 요리`로 표시해요. 검색 기준·모드 규칙을 새로 만들지는 않았어요.

## answer_plan

| 화면 | 구성 |
| --- | --- |
| 종류 질문 | text → question → chips, 카드 없음 |
| 지역 질문 | text → question → chips, 카드 없음 |
| 메뉴 후보 | text → menu_cards → notice → chips(다른 메뉴 보기) |
| 첫 식당 검색·동행 질문 | text → place_cards → source → question → chips |

종류 질문의 두 표현은 하나의 질문 블록에 함께 들어가요. 모델이 만든 질문을 칩으로 복사하지 않으며 `answerLayout`·`answerChoices`가 질문 슬롯과 화면 배치를 연결해요.

## 테스트 결과

- `node scripts/build-worker.mjs && node scripts/policy-smoke.mjs`: 전체 통과.
- 신규 `question-stages-smoke.mjs`: 네 화면의 answer_plan, 종류 타일 6개와 전체 폭 맡기기 버튼, 지역 답 8개와 위/그리드/아래 순서, 동행 칩 4개+생략 칩, 카페·디저트 경로, 실제 라우팅 함수가 만드는 전송 문장, 낮은 분류 신뢰도에서 명시적 답 처리, 선택 이력 유지, 잘못된 라벨 필터, 이전 저장 라벨 마이그레이션을 검증했어요.
- 기존 v119~v122 문체·FAQ·비교·검색·이력·인접 지역·대안·구성표 테스트도 통과했어요.
- 360px/390px: 실제 인라인 렌더러의 DOM과 CSS 계약을 모킹해 확인했어요. 좌우 16px, 아바타 32px, 간격 8px 기준 답변 폭은 각각 288px/318px이고, 3열 타일 폭은 약 90.7px/100.7px이에요. 긴 타일 라벨은 15px 글자로 줄바꿈할 수 있어 잘라내지 않아요.
- 인라인 JS 구문 검사·`git diff --check`: 통과.
- **실제 브라우저 픽셀 렌더·스크린샷·실기기 확인은 미완료**예요. CSS/DOM 확인을 실제 브라우저 확인으로 보고하지 않아요.
- 키 파일 확인·실제 AI 평가·실제 검색 API 호출은 하지 않았어요. 모든 외부 응답은 모킹했어요.
