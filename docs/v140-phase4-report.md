# v140 — 4단계 / 사용자 승인 가상 데이터 체험

## 실제 데이터 연동 여부

**미완료·차단:** 실제 추천 DB는 작업 중이라는 사용자 답변을 받았다. 앱 등록 추천 원본, 실제 메뉴·가격·작성자·이유·영업정보는 제공되지 않았다. 운영 설정 `data/recommendation-source.json`의 enabled/connected는 false로 유지했다. 가상 데이터 검증을 실제 DB 연동 완료로 보지 않는다. 실제 연결에 필요한 것은 공개 가능한 식당 주소/상호/좌표/업종, 메뉴명/가격, 추천 ID/작성자/원문/작성일/태그, 확인 근거가 있는 1인 이용 정보 및 유효한 영업 일정이다. 입력 어댑터는 `docs/recommendation-data.md`를 따른다.

## 구현 / 부분 완료

- 홈의 **가상 데이터로 추천 기능 체험** 또는 `/?demo=1`에서만 명시적 가상 체험을 시작한다. 상단 상시 배너, 상호·추천인·각 카드 출처에 가상 표시. 3개 식당과 추천 3/1/0건, 메뉴·가격·혼밥 근거의 차이를 가진다. 데이터 생성 위치는 선택 기준점 주변이므로 실제 식당 위치가 아니며 지도 버튼은 비활성이다. 사진은 만들지 않았다.
- 가상/일반 대화의 localStorage·sessionStorage 키를 분리했다. 서버도 모드가 다른 상태를 승계하지 않고, 화면도 다른 모드 카드를 받지 않는다. 가상 화면에서는 공유 버튼을 숨긴다. 일반 네이버 결과에 가상 추천을 붙이지 않는다.
- 원문 이름/이유의 동일 레코드 연결, 관련성→작성일→ID 대표 선정, 조건 변경 재선정, 추천 건수 기준 펼침을 기존 어댑터로 처리한다. 가상 데이터도 AI 생성 없이 명시적으로 작성된 고정 레코드다.
- 일반 점심·저녁 및 방문 예정은 맥락이며 영업정보 누락만으로 추천을 중단하지 않는다. 명시적 `영업 중인 곳만`은 필수 조건이다. 업종 확인(`food_category`)과 특정 메뉴 판매(`menu`)를 구분한다. 예산은 등록된 해당 주 메뉴 가격, 혼밥은 객관적 근거/추천인 경험을 구분한다.
- 영업정보 어댑터는 `openingSchedule`의 출처·Asia/Seoul·유효기간 `[validFrom,validUntil)`·일별 분 단위 구간을 요구한다. 정확한 방문 시각을 해석할 수 없거나 유효한 정보가 없으면 미확인이다. **주간/휴일/임시휴무/자정 넘김 일정과 실제 외부 영업시간 조회는 미연동**이며 이 축약 형식으로 임의 보장하지 않는다. 현재 실제 데이터는 없어 가상 일정만 시험했다.
- 미확인 표시 동의는 현재 대화의 항목 키별로 유지한다. 거리 변경으로 반복 묻지 않고 새 항목(예: 주차)만 묻는다. 예산 초과처럼 확인된 불충족은 동의해도 제외한다. 새 대화/모드 변경에는 승계하지 않는다. 이 동의는 거리나 조건 완화가 아니다.
- 공통 미확인 문장은 목록 위 한 번, 각 카드에는 짧은 상태와 독립적인 **확인 상태 자세히/접기**를 둔다. 추천 원문과 메뉴·가격을 주소보다 먼저 보여준다. 사진 누락은 짧은 텍스트이며 큰 빈 사진 영역은 없다. 지역 시트의 구현 용어를 사용자 안내로 바꿨다.

## 검증 환경 / 재현 절차

- `node scripts/build-worker.mjs` 및 `node scripts/policy-smoke.mjs`: 통과. 실제 AI 호출/평가·키 조회 없음. 모든 테스트 네이버 호출은 모킹.
- `scripts/phase4-smoke.mjs`: 점심→강남역 3곳, 영업 필수 게이트, 업종 확인, 동의 후 500m 변경, 새 주차 항목만 재확인, 새 대화 동의 초기화, 가상/일반 분리, 대표 선정·조건 변경, 9천원 확인·1만3천원 탈락, 여러 추천 건수, 명시적 내일19시 가상 일정 판정, 메뉴·가격 상세 답변.
- 클라이언트 실제 함수+테스트 DOM: 원문 펼침/접기와 상태 상세는 API·조건·지도 URL을 바꾸지 않는다. 가상 지도 비활성, 일반 주소 URL, 새로고침/버전 복원, 위치 권한 성공/거부/실패/시간초과 모킹 등 기존 회귀 포함.
- 로컬 exact compiled Worker + mocked upstream, IAB viewport **360×900 / 390×900**: 가상 카드 3개, 펼침·접기, 혼밥 대표 변경, 동의 후 확인/미확인 그룹 분리, 상태 상세 표시 확인. 카드 가로 넘침 없음(각각279px/309px). 가상 지도는 비활성. 확인 화면은 workspace 외부 산출물 `work/qa-v140/demo-360-expanded.png`로 보관한다.

## 미검증 / 남은 문제

- **실제 데이터 연동, 실제 추천인 원문 정합성·가격/혼밥/영업 조건 충족 검증은 미완료**. 데이터 수령 후 운영 공개·접근 정책 검수와 실데이터 재검증이 필요하다.
- 실제 휴대폰 GPS 성공, 소프트키보드·터치, 네이티브 지도 앱 왕복은 미검증. 브라우저 viewport와 위치 모킹을 실제 기기 검증으로 보고하지 않는다.
- 지도는 일반 카드의 전체 주소 검색이며 상세/길찾기 보장이 아니다. 가상 카드에는 실제 주소가 없어 지도 왕복 시연을 하지 않는다.
- 배포/같은 커밋 GitHub 동기화 결과와 라이브 점검은 완료 응답에 별도로 보고한다.
