# 요청서 3단계 — v139 구현·검증 보고

## 1. 수정 내용과 실제 데이터 연결 상태

확인 시점의 `data/recommendation-source.json`은 enabled=false, connected=false, source=null이다. `.openai/hosting.json`의 D1/R2 바인딩도 null이다. 실제 앱 원본 파일이나 DB 응답은 제공되지 않았다. 서버에 과거 원격 DB 어댑터 함수가 남아 있었으나 v137 이후 정상 추천 경로는 네이버를 직접 호출했다. v138 추천 로더는 작성 원문 병합 전용이었고 식당 자체를 먼저 조회하지 않았다. 이번에 **연결된 정적 원본의 좌표 있는 식당을 우선 검색하고, 부족할 때 네이버 검색으로 보완**하도록 보완했다. 등록 식당 3곳이 있으면 네이버 호출을 생략한다. 등록 추천만 요청했는데 원본이 꺼져 있으면 미연결을 안내하고, 동의 없이 네이버로 바꾸지 않는다.

실제 데이터 연동 완료가 아니다. 등록 데이터 우선 경로, 대표 추천, 펼침, 가격·1인 이용 정보는 테스트 전용 원본으로 검증했다. 배포 데이터에는 가상 이름·이유·메뉴·가격·좌표를 넣지 않는다. 실제 배포는 추천 원본 플래그를 계속 끈다.

### 조건 저장 ≠ 조건 확인

- 카드에 조건별 `confirmed` / `experience` / `unknown` / `failed` 상태와 근거를 붙인다.
- 거리: 실제 선택 기준점과 식당 좌표의 Haversine 직선거리. 범위 밖은 제외한다.
- 음식: 연결된 등록 업종 또는 등록 메뉴로만 확인한다. 검색어 포함만으로 메뉴 판매를 확인했다고 하지 않는다.
- 예산: 연결된 **주 메뉴(mainDish=true)**의 가격이 요청 한도 이내인지 확인한다. 확인된 해당 주 메뉴가 예산을 넘으면 제외한다. 가격이 없으면 미확인이다. 저렴한 음료·사이드 가격으로 통과시키지 않는다.
- 혼밥: 등록 1인 이용 근거(source가 있는 soloEvidence)와 추천인의 작성 경험을 구분한다. 추천 경험은 좌석 보장이나 객관적 시설 확인으로 표시하지 않는다.
- 방문 시점 영업 여부: 해당 시점에 사용할 영업 데이터가 없으므로 미확인이다. 실제 조회/영업 확인 기능을 구현했다고 주장하지 않는다.
- 모르는 조건이 있으면 식당을 곧바로 조건 충족 카드로 보여주지 않는다. 먼저 미확인 항목을 안내하고 **[미확인 후보 보기]** 동의를 받는다. 확인된 식당이 일부 있으면 먼저 보여주고 나머지에 대한 동의를 묻는다.
- 등록 원본 자체가 미연결이고 메뉴·예산·인원·방문 시간 등 확인할 수 없는 조건이 있으면 **네이버 조회 전** 동의를 받는다. 연결된 데이터가 있다면 원본을 조회해 조건을 확인하며, 부족한 항목이 있는 식당 노출 전에 동의를 받는다.
- 동의한 뒤에도 미확인 식당은 별도 구역과 카드별 미확인 근거로 표시한다. 조건을 바꾸면 동의는 초기화한다. 검색 조건을 자동 완화하지 않는다.

### 카드·화면

- 카드마다 앱 등록/네이버 검색/네이버+등록 추천 연결 출처를 표시한다.
- 등록 사진이 있을 때 상단 사진, 없으면 작은 사진 정보 없음 문구(빈 사진 틀 없음). 메뉴·가격, 직선거리, 주소 보조 정보, 추천 원문, 조건별 근거, 지도·비교 행동을 표시한다.
- 추천 이름과 이유는 동일 ID의 원문 그대로이며 AI 문체 변환을 하지 않는다. 추가 추천은 사람 수가 아니라 대표 외 추천 건수다.
- 실제 브라우저 클릭에서 발견한 기존 카드 전체 링크의 투명 `::after`가 펼침 버튼을 덮던 문제를 제거했다. 지도 제목 링크·지도 버튼·비교·추천 펼침은 독립 동작한다.
- 조건 칩에 변경 표시와 접근성 이름, 44px 해제 영역을 유지한다. 지난 조건 줄은 숨기고 최신 조건 줄만 보인다. 위치는 변경 선택, 거리는 범위 변경이며 삭제 버튼이 없다.
- 거리 시트의 현재 값 강조, 500m/1km/2km, `예: 800m, 1.5km` 직접 입력과 전체 폭 입력란을 추가했다.
- 현재 위치는 권한 대기와 좌표 수신 문구를 구분한다. 5초 후 지역 입력으로 전환 가능하며 늦게 도착한 좌표는 취소된 흐름에 적용하지 않는다. 실패 이유별 안내·지역 선택·직접 입력·위치 재시도를 유지한다.
- 상단 ‘시작하기’를 실제 기능인 ‘새 대화’로 수정했다. 활성 대화 ID를 탭의 sessionStorage에 저장해 일반 새로고침에도 복원한다. 새 대화는 이 ID를 지우며 이전 이력을 자동 혼합하지 않는다. 공유 화면은 로컬 활성 대화를 자동 복원하지 않는다.
- 시간대 질문 3개, 기본 1km, 주소만 검색하는 지도 링크, 비교 트레이, 오류 재시도, 키 없는 모킹 검사 경로를 유지한다.

## 2. 검증 환경·시나리오

Node.js 빌드와 policy-smoke는 네이버를 모킹하며 AI/실제 키를 사용하지 않는다. 등록 데이터 검사는 `tests/fixtures/`에서 만든 build/의 테스트 전용 Worker를 사용한다. 이전 카드 시나리오는 v139 동의 단계를 명시적으로 진행한 뒤 계속 검사한다. 동의 전 차단 검사는 별도의 raw request 및 실제 클라이언트 경로로 검사한다.

| 필수 시나리오 | 확인 범위 | 결과/한계 |
|---|---|---|
| 1 지역·역 → 위치만 1km | Worker/실제 클라이언트 모킹, 로컬 브라우저 성수역 | 통과 |
| 2 현재 위치 성공 → 1km | 권한 granted/prompt·좌표 수신 모킹, Worker 거리 계산 | 통과, 실물 기기 GPS 성공 미검증 |
| 3 위치 실패 → 복구 | denied/unavailable/timeout/insecure/unsupported, 지역·직접 입력·재시도 | 모킹 통과, 실기기 미검증 |
| 4 한식·예산·혼밥 | 미연결 시 동의 전 카드 차단 / 원본 fixture의 9천 원 주 메뉴·1인 근거 / 초과 가격 제외 | 통과. 실제 DB 조건 충족 검증은 아님 |
| 5 거리 변경·예산 해제 | 다른 슬롯 유지·동의 범위 초기화·시트 선택 표시 | 통과 |
| 6 여러 추천 펼침 | 원문 쌍·N=2·동일 작성자 별개 ID·0/1건·카드별 DOM·360px 실제 클릭 | 통과(가상 데이터) |
| 7 혼밥 대표 재선정 | 관련성 > 날짜 > ID, 선택 조건 변경 후 원본에서 재선정 | 통과(가상 데이터) |
| 8 0건 → 사용자 범위 선택 | 1km 유지, 2km 버튼을 선택한 이후만 변경 | 통과(모킹) |
| 9 지도 클릭·복귀 | 전체 주소 URL·주소 없음 비활성·클릭 전후 조건/목록 불변 모킹 | 통과. 실제 네이버 지도 왕복은 별도 확인 필요 |
| 10 시간대 경계/생성 실패 | 09:59/10:00, 13:59/14:00, 16:59/17:00, 20:59/21:00, 자정/04:59/05:00·폴백3개 | 통과 |
| 11 모바일 | PC 브라우저의 360/390px 실제 뷰포트, 긴 원문·펼침·거리 시트·조건 표시 | 브라우저 시각 확인. 실물 휴대폰·가상 키보드·지도 앱 미검증 |

로컬 QA는 화면에 **가상 데이터·실제 DB 연동 아님**을 표시한다. 화면과 측정 기록은 작업 폴더 `work/qa-v139/`에만 저장하며 실제 데이터 증빙으로 쓰지 않는다. 새로고침 후 동일 대화·조건·목록이 유지되는 것은 로컬 브라우저에서 확인했다.

## 3. 필요한 데이터와 남은 문제

1. 실제 앱의 식당 원본(상호, 도로명/지번주소, 업종, 위·경도)과 동일 추천 ID의 추천인 이름·원문 이유·작성시각·태그가 필요하다. 추천 원본만 있고 식당 좌표가 없으면 네이버 결과에 주소 병합은 가능하지만 등록 식당 단독 거리 검색은 불가능하다.
2. 실제 메뉴명·주 메뉴 구분·가격, 1인 이용 근거와 출처, 허용된 대표 사진 URL이 필요하다. JSON 스키마에 추가했고, CSV에는 선택 열 `category,latitude,longitude,imageUrl,menus,soloEvidence`를 지원한다. menus/soloEvidence는 JSON 셀 값이다. 실제 Excel 원본을 변환해 검증한 것은 아니다.
3. 방문 시점 영업 확인에는 정기 영업시간·휴무·브레이크타임·임시휴무·유효기간 등 별도 데이터가 필요하다. 현재는 안내와 동의만 제공하며 실제 영업 조회는 미구현이다.
4. 지역·역 직접 입력을 유지하지만 현재 좌표 테이블은 강남역·역삼역·홍대입구역·합정역·성수역·종로3가역·여의도역뿐이다. 다른 지역의 임의 역으로 바꾸지 않는다. 전국 동네·역의 확장 좌표 데이터/지오코더 연결은 남아 있다.
5. 실제 데이터 매칭률, 실제 사진 로드, 실제 추천인 원문 정합성, 대규모 데이터 성능, 실물 모바일 GPS/키보드/지도 앱 왕복은 미검증이다. 데이터 연결 전에는 이를 완료로 보고하지 않는다.
