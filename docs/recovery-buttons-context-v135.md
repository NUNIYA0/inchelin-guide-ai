# v135 — 무응답 방어, 버튼 단순화, 필요한 질문만

## A. 무응답 경로 점검

첫 화면 추천 행과 타이핑은 모두 newChat → routeQuestion → ask → generateAnswer → POST /api/chat 경로다. 성수 전용 프리셋이나 별도 요청 경로는 없다. 5개 추천 행 각각에 대해 실제 프런트 핸들러·요청·렌더링과 직접 입력 경로를 모킹으로 비교했다.

코드에서 확인·재현한 문제:

- 사용자 말풍선 렌더 뒤 saveConversation의 localStorage.setItem 예외가 ask를 중단시킬 수 있었다. 저장 한도/권한 오류와 사이드바 렌더 오류를 검색 실패와 분리했다. 메모리 이력은 유지하며 기존 저장 이력을 삭제하지 않는다.
- 활성 요청의 AbortError를 무조건 무시해서 로딩만 사라질 수 있었다. 명시적인 새 대화 이동은 이전 요청을 조용히 무효화하되, 활성 대화의 예기치 않은 중단에는 안내·대안·재시도를 보여준다.
- 응답 렌더 직전에 로딩을 제거하던 순서를 바꿨다. 요청 준비·파싱·렌더 오류까지 같은 안내 경로를 사용하며, 응답 또는 오류 표시를 마친 뒤 로딩을 정리한다.
- 로딩 점 유지, 20초에 ‘조금 더 걸리고 있어요’, 45초에 시간 초과 안내로 전환한다. 실제 대기 없이 가짜 타이머로 검증했다.
- 0건, HTTP/파싱/불완전 응답/버전 불일치/중단/설정 실패에 안내 + [다른 지역][다른 음식] + [다시 시도]를 제공한다. 0건의 슬롯·응답은 이력에 유지하고 다시 열어도 재시도할 수 있다. 버전 불일치에서 재시도는 새 버전을 불러오는 새로고침이며 안내에 이를 명시한다.

제보 당시 브라우저의 저장소·요청 로그는 조회하지 않았다. 따라서 위 결함을 성수 2회 제보의 유일한 원인으로 단정하지 않는다. 0건·파싱·시간초과·버전 가드를 점검하고 각 경로의 무표시 종료를 방어한 변경이다. 원문 키 파일이나 런타임 키를 확인하지 않았다.

## C. 후속 질문 정책

- 맛집 요청에서 지역이 없으면 지역 하나부터, 지역만 있으면 음식 종류 하나를 질문+칩으로 묻는다. 두 값 모두 없는 맛집 요청도 지역부터다. 별도의 ‘오늘 뭐 먹지’ 메뉴 고민·종류 선택 흐름은 유지한다.
- 지역+음식이 있으면 결과부터 보여주고 자동 ‘누구와 가세요?’ 질문은 붙이지 않는다. 필요한 예시 2~3개를 사용자 말투로 제안한다.
- 지역·음식·동행·예산·분위기/시설 선호를 상태에 유지한다. 확정된 동행이나 선택한 분위기·시설을 예시로 되묻지 않는다. 이미 물었던 부족 슬롯도 반복하지 않는다.
- 조용함·단체석 예시는 확인 질문이 아니라 선호 추가다. 선택하면 ‘매장 확인이 필요해요’를 보여주고 기존 후보 수를 줄이지 않는다. 확인된 근거가 없으면 임의로 우열·시설을 만들지 않고 순서를 유지한다. 예산 역시 가격 데이터가 없어 선호로 기록·고지하며 필수 단계로 강요하지 않는다.
- 질문 구역과 예시 합계 최대 3개. 직전 예시의 축은 다음 턴에서 제외하며, 선택한 문장/의미는 세션 중복 검사로 제외한다. 상황·분위기·시설 축을 분리해 불필요한 같은 축 반복을 피한다.
- 서비스는 고정 FAQ + 대안 칩만, 오류·0건도 대안 칩만 제공한다. 미확인 검색 결과를 만들어 예시 개수를 채우지 않는다.
- 식당명·서버 분류/존재 검증, v134 원 후보 유지, 음식·지역 검증, 현재 규칙 버전 가드는 유지한다. RESPONSE_RULES_VERSION은 v135다.

## 검증

- node scripts/build-worker.mjs: 35개 자산 포함 빌드.
- node scripts/policy-smoke.mjs: 신규 v135 및 기존 모킹 회귀 전체 통과.
- 신규: 5개 추천 발화 × 추천/타이핑, 실제 프런트 5행 경로, 0건·통신·AbortError·JSON·버전·불완전 응답·중단·20/45초·저장소 한도.
- 정책: 지역만/음식만/둘 다 없음/둘 다 있음, 회식 중복 미노출, 직전 축 제외, 조용함 선택 후 3곳 유지+확인 고지, 예산 유지, 서비스·0건 대안.
- 기존: 4개 지역/음식 × 동행 4종의 3→3, 메뉴/비교/핀/지도 링크/새 대화 분리/이력/키보드 등 유지.
- 키 확인·실제 AI/Naver 평가·실사이트 대화 테스트 없음. 배포 성공은 Sites 결과로 확인하며 공개 범위는 public 유지.
