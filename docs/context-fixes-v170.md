# v169 피드백 반영과 50발화 재검증 준비

## 수정

1. **반경 확정:** AI가 추천/조건 변경으로 이해한 요청의 숫자·단위를 프로그램에서 정규화한다. 실제 반경 질문을 기다리는 상태에서 `1km`처럼 단위가 있는 숫자만 답하면 선택 버튼과 동일한 입력으로 처리한다. 기본값과 숫자가 같아도 radiusConfirmed=true와 explicit 출처로 저장한다. 설명/FAQ/상세 조회에 등장한 거리는 변경으로 처리하지 않고, 여러 거리 후보·명시적 해제는 임의 확정하지 않는다.
2. **예산 질문:** `missing_budget`로 이해한 요청에서 `set/null` 또는 상대적인 예산 값을 저장하려다 예외가 나는 대신 금액을 묻는다. 기존 예산은 유지하고 숫자를 임의 생성하지 않는다.
3. **정보 기능:** 모델이 정보 목적을 informationRequest로 명시하고, 서수 대상은 referencePositions로 표현할 수 있게 했다. 서버는 실제 카드 ID로 연결한다. 비교 요청이 일반 답변 action으로 왔어도 의미가 compare_places라면 실제 조회/비교 도구를 실행한다. 두 곳을 비교한 뒤에는 단일 식당 focus를 임의로 첫 식당으로 두지 않는다. 모델 지침에 우열 판단 불가와 사실 비교를 분리했다.
4. **검색 연결:** v169에서 빠졌던 운영 호출의 progressive 옵션과 진단 연결을 실제 Worker 경로에 추가했다. 최대 24개, 4개씩 조회하며 실제 거리·메뉴·예산 조건을 변경하지 않는다. 이번에는 helper 단위 테스트뿐 아니라 운영 /api/chat 경로의 searchDiagnostics.candidateLimit=24를 회귀 테스트로 확인한다.
5. **영업 시각:** 모델이 `지금`과 `기존 방문 시각`을 구분한다. current이면 서버의 현지 시각을 사용하고 이전 방문 시각을 덮어쓴다. requested_visit이면 기존 구체 시각을 유지한다. 영업 일정이 없을 때는 계속 미확인으로 처리한다.

## 보존

실제 등록 1,099곳과 추천인/메뉴/링크의 연결, 현재 UI·알약 버튼·조건 표시 텍스트·네이버 플레이스 상세 우선/검색 폴백, 대화 이력 복원은 유지한다. 키 파일은 조회·변경하지 않는다. 실제 평가는 기존 배포 사이트의 서버 연결을 이용한다.

## 검증

build-worker + policy-smoke에 반경 답변 누락 복구, 설명과 조건 변경 분리, 금액 미정 질문, 서수 비교의 실제 ID 연결, 비교 후 단일 focus 없음, 운영 단계적 검색 연결, 현재/예약 영업 시각 구분을 포함한다.

실제 재검증은 기존 30개를 유지하고 20개를 추가한 50개 발화다. 추가 범위는 800m/1.5km, 거리 설명, 예산 추가/해제/상대 표현, 상세 대상/모호한 지시어, 구체 방문 시각과 영업 조건 해제, 0건 시 명시적 확대, 정보 날조 요청 거부, 좌표 없는 현재 위치 요청이다. API 시험은 실제 GPS 권한이나 모바일 앱 전환을 대체하지 않는다.

실제 재검증 성적은 별도 QA 보고서의 원문 응답과 비교해서 보고한다. 단위 테스트 통과를 실제 50개 성공으로 간주하지 않는다.
