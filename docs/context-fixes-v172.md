# v172: 전 대화 여정 100턴 검증

## v171 실제 실패 5건 보완
1. 미확인 후보 확인 질문에 실제 발행한 선택지와 동의 계약을 기록한다. 같은 문장을 버튼이나 직접 입력으로 답하면 모델 분류 이후 계약을 검증하여 명시 동의를 누락하지 않는다. 임의의 새 조건 동의로 확대하지 않는다. 조건 변경 전 스냅샷과 비교해 새로운 미확인 조건은 재확인하며 거리 변경은 기존 동의를 유지한다.
2. resetBoundary로 화면 기록과 AI에게 전달할 문맥을 분리한다. 초기화 이전 메시지는 모델 입력과 근거 인용 대상에서 제외한다. 화면상의 기록은 보존한다.
3. resultRequest=new_results를 구조화된 모델 출력에 추가하여 FAQ/상세/비교가 끼어도 이미 본 식당 제외 요청을 search_more로 연결한다.
4. referenceKind로 상호·서수·단수 지시어·전체·모호함을 구분한다. 단수 focus가 없는 상태의 '거기'는 대상 확인으로 돌아가며 여러 식당을 모두 답하지 않는다.
5. 지도 단독 요청 예시와 도구 지침을 명시하고 map 실행 시 메뉴/전화/영업 세부 필드는 제거한다. 현재 위치 실패에 역 이름을 잘못 묻던 안내도 수동 지역 입력 안내로 정리한다.

## 검증
- build-worker, policy-smoke. 실제 운영 Worker 경로에 모의 모델/좌표 제공자를 연결하여 FAQ→다른 식당, 비교→모호한 대상, 지도 단독 응답, 초기화→과거 근거 차단, 동의→거리 변경→새 미확인 조건 재확인을 검증한다.
- 실제 검증은 별도 QA 도구에서 공개 /api/chat에 총 100회, 20개 독립 대화 × 5턴. 각 대화 안에서는 최근 실제 응답·조건·카드 ID를 다음 발화로 전달한다. 실패를 숨기는 자동 재시도는 없다. 기존 10개 여정과 새 10개 여정을 구분한다.
- 추천에 한 번 도달하는 것과 전체 흐름 통과를 구분한다. 최종 성적은 실제 응답 원문·전체 대화 검토를 포함한 QA 보고서로 제공한다. 0건 뒤 사용자가 조건을 해제해 일반 식당을 찾은 경우 원래 특정 음식 요구가 충족됐다고 기록하지 않는다.
- 실제 기기 GPS, 모바일 렌더, 외부 지도 앱 전환/복귀는 API 테스트로 검증하지 않는다. 키 파일은 조회·복사·생성하지 않는다. 실제 1,099개 식당 데이터와 기존 UI는 유지한다.
