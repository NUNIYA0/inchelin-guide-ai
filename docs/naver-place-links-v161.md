# v161 네이버 플레이스 상세 연결

## 원인과 수정

실제 2026-10-26 엑셀의 1,099곳 모두에 서로 다른 `naverPlaceUrl`이 있었다. 주소 검색 방식으로 바꾸던 예전 정책이 좌표 보강(`registered-search`), 결과/상세 응답(`index.template`), 브라우저 정규화(`normalizeRestaurant`)에서 이 URL을 덮어썼다.

이제 원본 상세 URL과 상호·주소 매칭 기록을 보존한다. 현재 원본의 매칭상태는 상호·주소 일치 906곳, 주소 일치·상호 표기 차이 185곳, 이전·상호 변경 등의 대조 확인 8곳이다. 이것은 **원본 수집자의 매칭 기록**이며 이번 작업에서 1,099곳의 현재 페이지를 전부 재검사했다는 뜻이 아니다. URL 형식·ID 유일성·검증 메타데이터 보존은 전수 테스트했다.

## 링크 정책

- `naverPlaceUrl`: 확인된 네이버 상세 URL. `naverPlaceId`는 해당 URL에 실제 들어 있는 숫자 ID만 추출하거나, 운영자가 확인한 ID를 사용한다. 이름·주소·좌표로 ID를 생성하지 않는다.
- `naverPlaceVerification`: `status:verified`, 원본과 일치하는 `name`, `address`, `checkedAt`, `source`, 선택적 `placeId`로 매장/지점을 묶는다. 상호·주소나 ID가 서로 다르면 상세 연결을 거부한다.
- 기존 엑셀의 알려진 매칭 상태와 수집일은 `registered-workbook` 근거로 보존한다. 다른 출처의 새 링크는 검증 기록 없이 상세 링크로 승격하지 않는다.
- 지역 검색 API `link`는 업체 홈페이지일 수 있다. 공식 문서의 예시도 홈페이지다: https://api.ncloud-docs.com/docs/naver-api-hub-search-local . 일반 홈페이지·검색 URL·일반 `id` 필드를 플레이스 ID로 간주하지 않는다.
- HTTPS, 인증정보/임의 포트 없음, 정확한 도메인과 상세 경로를 검사한다. 허용 도메인은 `map.naver.com`, `m.map.naver.com`, `place.naver.com`, `m.place.naver.com`, `pcmap.place.naver.com`, 공유용 `naver.me`다. `*.naver.com` 전체를 허용하지 않는다.
- 검증된 상세 연결은 `지도 보기`. 없으면 매장명 + 중복되지 않는 지점명 + 전체 주소로 검색하고 `네이버지도에서 검색`으로 구분한다. 주소와 상세 링크가 모두 없으면 비활성화한다.
- 상세 목적지는 HTTPS 웹 URL `https://map.naver.com/p/entry/place/{확인된 ID}`다. 앱 전용 스킴/출발지/길찾기를 만들지 않는다.
- 과거 저장 카드가 상세 메타데이터를 잃은 경우 `/api/restaurant-place-link?id={등록 sourceId}`로 현재 등록 링크를 읽어 복원한다. 카드 이름·주소를 다시 대조하며 브라우저 캐시는 최대 1시간이다. 지도에서 복귀해도 대화·조건은 바꾸지 않는다.

## 신규 등록·수정 경로

기존 앱에는 식당 편집용 관리자 화면이 없다. 새 공개 편집 화면은 추가하지 않고 기존 JSON/CSV 어댑터와 운영자용 입력 스크립트를 제공한다.

JSON 식당 항목 또는 CSV의 `naverPlaceUrl`, `naverPlaceId`, `naverPlaceVerification` 필드를 사용할 수 있다. CSV의 verification은 JSON 문자열이다. 원본 이름·주소와 실제 페이지의 이름·주소를 먼저 확인해야 한다.

운영자는 다음처럼 네이버지도 공유/상세 링크를 등록한다. 값은 해당 식당의 실제 확인값으로 입력하며 예시 데이터를 배포하지 않는다.

```text
node scripts/register-place-link.mjs --source-id <등록식당ID> --url <네이버공유또는상세URL> --verified-name <확인한정확한상호> --verified-address <확인한정확한등록주소> --checked-at <확인날짜>
```

스크립트는 원본 등록 매장명·주소와 입력값이 다르면 저장하지 않는다. 공유 링크는 리다이렉트 목적지를 최대 5회, 매 단계 허용 도메인/HTTPS로 검사한다. 상세 목적지를 확인하지 못하면 실패하며 브라우저에서 직접 상세 URL을 확인해 입력해야 한다. 이 스크립트가 페이지 내용을 자동으로 읽어 상호·주소를 검증하는 것은 아니다. 운영자의 사전 대조가 필요하다.

확인한 링크는 Git에 제외된 `data/private/place-links.json`에 sourceId와 매장명·주소를 함께 저장한다. 다음 빌드에서 정확한 식당에만 병합한다. 원본 엑셀을 변경하거나 다른 지점에 이름만으로 병합하지 않는다.
