# 음식 종류 × 지역 진입 (v117)

- 홈 입력창 아래의 공통 선택기에서 음식·지역을 선택한다. 둘 다 선택하면 `찾기`, 하나만 고르면 `한 가지만 정하고 이어가기`를 사용한다.
- 카테고리 찾기와 지역별 찾기는 같은 선택기 모듈을 호출한다. 결과 상단 조건 칩은 한 축만 편집하며 다른 축과 선호를 유지한다.
- 선택은 자연어 메시지로 기존 의도 분류 → 정책 → 검색 흐름에 들어간다. UI에서 식당 검색을 직접 호출하지 않는다.
- 음식 칩 10개: 한식, 고기, 찌개/국밥, 면, 일식, 중식, 양식, 분식, 카페, 술집. 세부 메뉴는 선택 사항이다.
- 카드: 식당명 / 음식·지역 칩 / 주소 / 상세보기·비교에 담기. 주소를 되풀이하는 이유는 없다. 주차·룸 등의 실제 안내와 사용자 조건이 연결될 때만 이유 한 줄을 허용한다.
- 지역명·행정동 별칭은 주소에서만 검사한다. 상호에 지역명이 있다는 이유만으로 통과시키지 않는다. 역 주변의 거리나 도보 시간을 보증하는 방식이 아니다.
- 0~2건이면 해당 개수를 안내하고 인접 지역·비슷한 메뉴를 제안한다. 선택 전에는 자동으로 검색 범위를 넓히지 않는다.

## 지원/모킹 테스트 범위

빠른 지역 칩 7개와 주소 별칭:

| 칩 | 주소 일치 별칭 |
| --- | --- |
| 강남 | 강남, 강남구 |
| 강남역 | 강남역, 역삼동, 서초동, 강남대로 |
| 역삼 | 역삼, 역삼동 |
| 홍대 | 홍대, 서교동, 동교동 |
| 성수 | 성수, 성수동 |
| 종로 | 종로, 종로구 |
| 여의도 | 여의도, 여의도동 |

인접 제안 주소 별칭도 모킹 검증한다: 합정, 상수, 뚝섬, 서울숲, 안국, 을지로, 영등포, 당산.

직접 입력은 별칭이 없으면 입력 지역명/동·역 어근을 주소에서 대조한다. 메뉴별 검색 결과나 전국 커버리지를 보장하지 않는다. 현재 위치는 사용자가 허용한 기기 좌표·역지오코딩을 사용한다.

검증은 모두 모킹이다. 실제 네이버 검색 성공률·식당 존재/영업 여부·브라우저 화면 QA는 이번 작업에서 확인하지 않았다. API 키 확인과 AI 평가는 실행하지 않는다.
