# AI 검색 기준과 음식·지역 정책 (v118)

## 이번 방향 수정

- 홈의 음식 종류 × 지역 선택기 블록은 제거했다. 홈은 입력창과 추천 질문만 유지한다.
- 선택기 컴포넌트는 삭제하지 않았다. 카테고리로 찾기·지역별 찾기 플러그인과 결과 상단의 한 축 변경에서 재사용한다.
- 음식 종류와 지역은 UI의 강제 진입 순서가 아니라 AI 검색의 최우선 슬롯이다.
- 카드 음식·지역 칩, 주소 반복 이유 제거, 결과 조건 칩, 음식/지역 불일치 제외, 0~2건의 정확한 개수 및 대안 칩은 유지한다.

## 슬롯 정책

- 분석 JSON의 food_type은 상위 음식 종류, menu는 선택적인 세부 메뉴다. 예: 냉면 → food_type=면, menu=냉면; 삼겹살/갈비/구이 → food_type=고기.
- 국물 있는 거 → 국밥·찌개, 홍대입구/홍대입구역 → 홍대, 역삼 쪽/역삼역 → 역삼, 강남역 근처 → 강남역으로 정규화한다.
- 음식과 지역이 있으면 즉시 검색하며 동행은 그 뒤에 물을 수 있다. 한 축이 없으면 없는 축 하나만 먼저 묻는다. 분위기·동행·예산·주차는 두 축을 대체하지 않는다.
- 거기 말고 성수에서 → 지역만 변경; 그럼 국밥으로 → 음식 축만 변경. 다른 축과 선호는 유지하며 이전 식당 제외 요청으로 오해하지 않는다.
- 맛있는 거처럼 음식이 모호하면 지역을 먼저 묻고 음식 선택·메뉴 탐색으로 연결한다.
- 특정 식당 정보·비교·서비스/FAQ는 검색 축 면담으로 바꾸지 않는다.
- 텍스트로 미지원 지역을 말하면 검색하지 않고 아래 7개 지역 칩을 안내한다. 음식은 유지하고 지역만 다시 고르게 한다. 챗봇 응답에는 확장 계획을 넣지 않는다.

## 지원 지역 (텍스트 검색)

| 지역 | 입력 별칭 예 | 결과 주소 확인 범위 |
| --- | --- | --- |
| 강남 | 강남구, 강남 | 강남/강남구 |
| 강남역 | 강남역, 강남역 근처 | 강남역/역삼동/서초동/강남대로 |
| 역삼 | 역삼동, 역삼역, 역삼 쪽 | 역삼/역삼동 |
| 홍대 | 홍대입구, 홍대입구역, 서교동, 동교동 | 홍대/서교동/동교동 |
| 성수 | 성수동, 성수역 | 성수/성수동 |
| 종로 | 종로구, 종로3가 | 종로/종로구 |
| 여의도 | 여의도동, 여의도역 | 여의도/여의도동 |

주소 일치는 역 반경·도보 시간 보증이 아니다. 상호에 지역명이 있다는 이유만으로 통과시키지 않는다. 메뉴와 지역이 함께 정해진 검색에서는 두 조건이 모두 맞는 결과만 카드에 붙인다. 현재 위치 연결은 기존 기기 좌표·역지오코딩 흐름을 유지한다.

### 확장 계획 (보고서 전용)

추가 지역 출시 일정은 미정이며 이번 배포에서 확장하지 않았다. 합정·상수 등 과거 주소 별칭이 코드에 남아 있어도 텍스트 검색 지원 목록은 위 7곳으로 제한한다. 대안 칩도 현재 지원 지역 안에서만 제시하며 인접 지역이라고 단정하지 않는다.

## 검증 결과와 한계

- `node scripts/build-worker.mjs && node scripts/policy-smoke.mjs` 통과.
- 사전 정규화, 분석 JSON의 food_type·region, 한 축 변경과 나머지 축 유지, 모호한 음식의 지역 우선 질문, 미지원 지역 검색 차단·지원 칩, 홈 선택기 미표시·플러그인 유지 테스트를 모킹으로 추가했다.
- v117의 카드·선택기·결과 검증 회귀도 함께 통과했다. 새 정책과 충돌하는 기존 비지원 지역 검색 테스트는 지원 지역의 동일 기능 테스트 또는 미지원 안내 기대값으로 바꿨다. 원본 평가 데이터셋은 수정하지 않았다.
- 인라인 브라우저 스크립트 문법 검사 통과(실행하지 않음).
- 키 확인·AI 평가는 실행하지 않았다. 실검색 성공률·실제 매장 존재/영업 정보와 브라우저 화면 QA는 미확인이다.
