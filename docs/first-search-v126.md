# v126 첫 검색·연관 질문·Enter 수정

## 확인한 코드 경계와 수정

### 추천 행 / 첫 메시지

추천 행은 원래도 별도 AI API가 아닌 `routeQuestion → ask`를 사용했다. 다만 홈 진입은 이전 대화 상태를 명시적으로 초기화하지 않았고, 응답에 `answer_plan`이 없으면 렌더러가 본문만 표시하는 기본 동작을 사용했다. 응답을 정상 성공으로 받아들이기 전에 카드/계획/질문의 일관성을 확인하는 검사도 없었다.

홈 추천 클릭과 홈 직접 입력을 `submitWelcomeQuestion → newChat → routeQuestion → ask → requestAssistant → renderMessage`로 통일했다. 이 경로는 이전 지역·카드·대화 ID를 비우고 새 요청을 만든다. 채팅 중 일반 후속 입력은 초기화하지 않는다.

추천 행 5개는 카드 검색 경로를 명확히 보여주도록 지역과 메인 메뉴가 모두 있는 예시로 정리했다:

| 추천 행 | 음식 / 지역 |
| --- | --- |
| 홍대에서 냉면 먹을래 | 냉면 / 홍대 |
| 강남에서 삼겹살 먹을래 | 삼겹살 / 강남 |
| 역삼에서 국밥 먹을 곳 찾아줘 | 국밥 / 역삼 |
| 성수에서 파스타 먹을 곳 찾아줘 | 파스타 / 성수 |
| 여의도에서 초밥 먹을 곳 찾아줘 | 초밥 / 여의도 |

계획 누락, 카드 수를 주장하지만 카드/블록이 없는 응답, 카드가 있어야 하는 성공 응답의 누락, 질문 블록 불일치는 성공 메시지로 저장하지 않고 `다시 시도`를 보여준다. 응답 수신은 30초 제한이며 시간초과도 재시도를 제공한다. 정상 0건 안내는 오류로 취급하지 않는다. 재시도는 동일 요청을 다시 보내며 사용자 메시지를 중복 생성하지 않는다.

라이브 API/로그/브라우저 재현은 사용자 요청에 따라 실행하지 않았다. 따라서 사용자가 본 실제 패킷에서 어떤 경계가 실패했는지는 단정하지 않는다. 위 실패 경계는 소스 검사와 불완전 패킷 주입으로 확인하고 차단했다.

### 첫 검색 구성 / 문구

이전 카드가 없는 명시적 지역+음식 검색은 잘못된 `condition_change` 힌트를 `place_search`로 교정한다. 기존 카드/이전 식당이 실제로 있는 후속 질문은 그대로 유지한다.

첫 검색 `ready` 단계는 조건 변경용 요약/이유(`새로 말씀`, `다시`, `바꿔`, `변경`)를 거른다. 문장 검사에 준비·처리·생성·분석과 명사형 종료 패턴을 추가하고, 모델의 첫 안내 문장은 완결된 해요체만 채택한다. 기존 1회 재생성 → 실패 시 템플릿 규칙을 유지한다.

일반 첫 검색은 문장 → 카드(최대 3) → 출처 → 누구와 가세요? → 칩 → 연관 질문을 유지한다. 동행을 이미 말했거나 즉시 보기 요청이면 기존 중복 질문 방지 규칙을 따른다. 연관 질문은 사전 검증이 실패하면 아래 규칙에 따라 줄이거나 생략한다.

### 연관 질문

- `place_search/condition_change/followup`은 지역·음식·상황 축만 우선 허용한다.
- FAQ 축은 `service/general`에만 허용한다. 검색 제안 검증 실패를 FAQ로 메우지 않는다.
- 비교는 실제 카드 2곳 이상이고 지역/음식/상황 제안이 하나 이상 남았을 때만 보조 1개를 허용한다. 비교만 남아 빈 검색 제안을 대신하지 않는다.
- 지원 지역·메인 메뉴 사전·기존 사전 검색/캐시/중복 검사를 유지한다. 사전 조회 예산 안에서 지역과 음식 축을 먼저 번갈아 확인한다.
- 검증 제안 1개도 그대로 보여주고, 0개면 연관 질문 블록을 빼며 빈 행은 그리지 않는다.

### Enter

화면 폭 768px 이상 **또는** `pointer:fine`이면 Enter 전송이다. Shift+Enter, `isComposing`, keyCode 229는 전송하지 않는다. 좁은 터치 화면은 전송 버튼만 사용한다. 넓은 화면에서 coarse 포인터가 감지되더라도 Enter를 막던 기존 조건을 제거했다.

## 검증

`node scripts/build-worker.mjs && node scripts/policy-smoke.mjs`

전체 기존 회귀와 다음 모킹 테스트를 실행한다. 네트워크 fetch는 모두 테스트 응답으로 대체하며 키 파일 확인·AI 평가·실제 AI/네이버 호출은 하지 않는다.

- 추천 행 5개 × 실제 클릭 이벤트 경로와 홈 직접 입력 submit 경로: 요청 내용/초기 상태 동일, 홈→채팅 전환, 카드 3장·출처·질문·칩·연관 질문 렌더
- 실제 요청 함수에 불완전 응답 주입 → 생성 catch → 다시 시도 버튼, 불완전 답변 미저장
- 첫 검색의 잘못된 condition_change 분석과 깨진 문구 주입 → ready/place_search 구성 및 해요체 폴백
- 검색 폴백에 FAQ 미포함, 0개/1개 검증 제안 처리
- Enter/Shift+Enter/IME/229/768 경계/작은 fine 화면/넓은 coarse 화면/모바일 터치
- 인라인 JavaScript 문법 및 diff 공백 검사

실제 모바일·데스크톱 브라우저 화면과 라이브 네이버 검색 재현은 **미완료**다. 배포 성공은 Sites 배포 결과로 확인한다.
