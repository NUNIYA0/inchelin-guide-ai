# v136: 질문 응답·조사·검색·맥락 승계

## 변경과 원인

1. 클라이언트 `requestAssistant`가 같은 버전의 새 HTTP 응답에도 저장 기록용 `isCurrent`를 적용했다. 서버 시각이 브라우저보다 조금이라도 앞서면 `age >= 0` 검사에서 탈락하고 `response_rules_changed`를 던졌다. 버전이 같은데도 버전 오류가 되는 경로를 서버 시각 +60초/-2시간 모킹으로 재현했다. 빠른 질문 응답에서 두드러질 수 있으나 제보 기기의 실제 시계 차이는 측정하지 않았다.
   - 새 네트워크 응답: 명시적으로 버전이 다를 때만 새 버전 안내. 누락된 메타데이터·JSON 파싱·렌더 예외는 일반 오류+다시 시도.
   - 브라우저 보관 유효기간은 로컬 수신 시각 기준. 서버에 돌려주는 상태의 시각은 서버 기준을 유지한다. 기록 TTL 1시간과 구버전 무효화는 유지.
   - 카드가 없는 질문 상태에도 서버 버전·시각을 일관되게 부여한다.
2. 지역만 있으면 “홍대에서 어떤 음식이 끌리세요?”로 질문한다. `korean.js` 공통 조사 함수를 종류/지역 답변 템플릿에도 적용하고, 공개 문장에 들어가는 확정 지역·음식 슬롯의 잘못된 조사를 최종 출력 경계에서 보정한다. 주소와 분석 필드는 고치지 않는다.
3. 동행·분위기·시설을 사용자 관점의 하나의 **상황 축**으로 묶어 한 응답에 최대 1개만 선택한다. 지역·음식·상황·상세·비교를 섞고, 비교는 2곳 이상일 때만. 한 곳이면 상황+지역/음식 축을 우선한다. 모델과 템플릿의 “다시 찾아줘”를 “찾아줘”로 정리한다. 결과 존재·의도 검증은 유지하고 실패한 제안은 억지로 채우지 않는다. 축 순환은 우선순위로 유지하되 지역/음식의 다른 값 재사용은 허용해 상황 중복으로 개수를 채우지 않는다.
4. `성수 파스타` 질의는 그대로 사용한다. 기존 필터는 음식명이 상호/분류에 글자 그대로 있어야 해, 네이버의 `음식점>양식>이탈리아음식`을 전부 버릴 수 있었다. 파스타에는 이탈리아음식/스파게티 분류도 매핑한다. 일반 양식·카페·고깃집을 무조건 허용하지 않으며 성수동 지번 주소의 지역 검증도 유지한다. 이는 검색 분류 근거이지 개별 메뉴판 확인이나 파스타 판매 보장은 아니다.
5. 지역만 바꾸고 직전 음식이 있으면 유지하며 “파스타 기준으로 찾았어요.”를 같은 응답에 표시한다. 직전 0건·이번 0건도 동일. 이전 음식이 없으면 음식 질문으로 이어간다. 문장 중복 검사에서 이 명시적 승계 고지가 삭제되지 않게 한다.

## 후속 인원 질문 정책

v135 요청의 “지역+음식이 충분하면 결과를 먼저 보여주고 선택형 예시 제공”에 따라 자동 `누구와 가세요?`는 의도적으로 제외된 상태다. v136은 이를 유지한다. 질문 함수 자체와 askedSlots/중복 질문 방지는 남아 있으며 사용자가 말한 동행 조건은 유지한다. v134 방식으로 자동 인원 질문을 복원한 것은 아니다.

## 운영 로그 점검과 한계

- 읽기 전용 로그 조회만 수행했다. 키/환경변수 조회, 실제 AI·네이버 검색 호출은 하지 않았다.
- 2026-10-22 11:27 KST의 `/api/chat` 200 타이밍은 검색 579ms, 문장 3969ms, 이어서 질문 650ms, 전체 5381ms였다.
- 11:26 KST 전후에는 분석 `turn_timeout` 뒤 `/api/chat` 200인 기록이 있다. 시간 초과 후 폴백이 작동한 기록이지 버전 불일치의 증거는 아니다.
- 기존 로그에는 성수 파스타 질의와 원본 검색 분류/탈락 사유가 없어서 제보한 실제 0건 원인은 확정할 수 없다. 위 분류 누락 경로는 모킹으로 재현·수정했다.
- 앞으로 `restaurant_search` 로그에 질의, 원본/최종 건수, 원본 분류 목록, 음식/지역 탈락 건수를 남긴다. 키·인증 헤더·원본 본문은 기록하지 않는다. 라이브 재현 후 이 로그로 실제 원인을 구분할 수 있다.

## 검증

`node scripts/build-worker.mjs` 및 `node scripts/policy-smoke.mjs` 전체 회귀 테스트. 외부 호출은 전부 모킹한다.

- 실제 클라이언트 함수의 `ask → requestAssistant → normalizeMessage → generateAnswer → renderMessage` 경로: 지역만/음식만/둘 다 없음/메뉴 고민, 각 서버 시계 0/+60초/-2시간, 질문 구역 표시·카드 없음·버전 오류 없음.
- 추천 행 5개와 직접 입력 동일 경로, 실제 버전 차이/메타 누락/JSON 오류 구분, 0건·중단·20/45초 복구 기존 테스트 유지.
- 성수 파스타 대표 검색 분류 fixture: 이탈리아음식 3곳 유지, 홍대 이탈리아집·성수 고깃집·카페 제외, 질의 `성수 파스타` 확인.
- 0건 이후 홍대 변경 시 파스타 유지+승계 고지, 음식 이력 없을 때 음식 질문.
- 은/는·이/가·을/를·으로/로·과/와, 단어 일부 오보정 방지.
- 상황 축 중복 없음, 1곳에서 비교 없음, “다시 찾아줘” 제거, 검증되지 않은 제안 미노출.

### 라이브 확인할 시나리오 — 아래는 모킹 결과이며 실제 대화 실행은 미실시

| 새 화면 입력 | 모킹 결과 / 라이브 기대 동작 |
|---|---|
| 홍대 맛집 추천해줘 | 홍대 유지, 음식 질문+종류 타일, 카드 없음, 버전 안내 없음 |
| 냉면 먹고 싶어 | 냉면 유지, 지금 어디세요?+위치/지역 버튼, 카드 없음 |
| 성수에서 파스타 | 이탈리아음식 분류를 포함한 성수 결과 표시. 실제 네이버 결과 수는 라이브 재확인 필요 |
| 강남에서 삼겹살 | 최대 3곳+출처+검증된 서로 다른 축의 이어서 질문, 자동 인원 질문 없음(v135 정책) |

실제 브라우저 픽셀 렌더 및 라이브 AI 대화/검색 품질은 확인하지 않았다.
