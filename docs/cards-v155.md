# v155 카드·대화 변경 및 사진 연결 상태

## 적용한 동작

- 기존 등록 1,099곳의 상호·메뉴·가격·추천인 연결을 유지한다. 추천인 작성 이유가 비어 있으면 `아직 등록된 추천 이유가 없어요.`를 표시하며 생성하지 않는다.
- 위치만 확정된 새 검색은 반경을 한 번 묻는다. 선택지는 500m / 1km / 3km이며 실제 직선거리 필터에 그대로 전달된다. 위치와 반경을 함께 말하면 바로 검색한다. 기존 대화의 확정 반경은 유지한다.
- 결과 조건은 일반 텍스트다. 결과 안의 조건 변경 버튼·화살표·편집 팝업은 제거했다. 최초 위치 선택과 자연어 변경은 유지한다.
- 식당 목록은 PC 약 두 장과 다음 카드 일부, 모바일 한 장과 다음 카드 일부가 보이는 가로 스크롤이다. 버튼·마우스 드래그·트랙패드·네이티브 터치·키보드 방향키/Home/End를 지원하고 자동 이동이나 순환은 하지 않는다. 단일 카드는 이동 UI가 없다.
- 사진 프레임은 2:1이다. 로딩 실패와 사진 없음 모두 프로젝트 서비스 로고와 같은 높이의 안내 영역을 유지한다. 추천인/이유는 본문에, 주소와 확인 정보는 상세 보기에 둔다. 지도는 전체 주소 검색이며 텍스트 버튼이다. 사이드바는 변경하지 않았다.

## 등록 사진 스키마

기존 식당 JSON 항목에 선택 필드 `photos`를 추가할 수 있다. 각 원소는 `url`(https 또는 /assets/ 경로), `isPrimary`(boolean)를 갖는다. 대표 사진을 우선하고 없으면 배열 첫 사진을 사용한다. 레거시 `imageUrl`도 지원한다. CSV/엑셀 변환본의 `photos` 열은 이 배열의 JSON 문자열이다. 사진 파일 업로드/관리 화면은 이번 범위에 추가하지 않았다.

현재 실제 원본에는 사진과 추천 이유가 없다. 임시 음식 사진이나 가상 추천 이유를 운영 데이터에 넣지 않았다.

## 외부 이미지: 어댑터 구현, 실제 연결은 미완료

`worker/restaurant-photos.js`는 공식 NAVER API Hub 이미지 검색 API를 서버에서 호출한다. 텍스트 추천이 먼저 렌더된 뒤 별도 `/api/restaurant-photo?id=...` 조회를 하므로 이미지 지연이 추천을 막지 않는다. 서버 제한 1.8초, 브라우저 제한 2.5초, 캐시 상한 1시간이다.

공식 문서: https://api.ncloud-docs.com/docs/en/naver-api-hub-search-image

이미지 검색 응답만으로 정확한 지점과 사용 권한을 입증할 수 없으므로 첫 결과를 바로 쓰지 않는다. `data/photo-source.json`의 `enabled`는 현재 false, `approvals`는 빈 배열이다. 실제 외부 이미지 호출·노출은 활성화하지 않았다. 기존 인증값의 이미지 API 사용 권한도 조회하지 않았다.

활성화에 필요한 자료:

1. 서버 환경의 `NAVER_API_HUB_CLIENT_ID`, `NAVER_API_HUB_CLIENT_SECRET` 및 이미지 API 이용 권한. 값은 브라우저/저장소/채팅에 넣지 않는다.
2. 식당별 `restaurantSourceId`, 원본과 같은 `restaurantName`, `roadAddress`, 실제 `imageUrl`, 원문 `sourceUrl`, `attribution`, `rightsBasis`, `identityVerified:true`, `rightsVerified:true` 승인 기록. 제공처 이용 조건과 이미지 권리 확인이 선행되어야 한다.
3. 등록 식당명·주소로 검색한 결과 중 승인 이미지 URL과 일치하고 상호도 확인되는 경우만 반환한다. 다른 지점·권리 미확인·시간초과는 사진 없음으로 남긴다. 노출 시 사진 출처 및 원문 링크를 표시한다.

## 검증 구분

- build-worker 및 policy-smoke: 반경 질문·직접 입력·거리 변경·실제 거리 필터, 조건 편집 제거, 사진 대표/첫 사진/없음/실패, 외부 사진 일치·권리 게이트, 캐러셀 경계/키보드/단일 카드/드래그 클릭 방지 확인. API는 모킹하며 AI 호출과 키 조회는 없다.
- 로컬 브라우저 PC 1280px 및 모바일 390/360px: 실제 등록 데이터와 모의 좌표로 카드 표시, 가로 목록, 페이지 가로 넘침 없음, 같은 높이/버튼 위치, 마우스 드래그·버튼·키보드 확인.
- 사진 로딩 성공·실패와 긴 추천 이유는 명시적으로 표시한 테스트 전용 화면에서 확인한다. 성공 사진은 서비스 로고이며 실제 매장 사진이 아니다. 테스트 작성자와 문장은 운영 응답에 포함되지 않는다.
- 미검증: 실제 매장 등록 사진, 실제 외부 이미지 제공/권리 연결, 물리 모바일 기기 터치 스와이프·가상 키보드, 실제 현재 위치 권한 성공. 기존 실제 좌표·지도 연결은 변경하지 않는다.
