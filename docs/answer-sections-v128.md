# v128 응답 구역과 의도 기반 이어서 질문

v127은 이미 공개 배포된 상태여서 추가 수정은 v128로 저장·배포한다. 기존 카드·비교·복사·입력 기능을 유지한다.

## UI

- 결과 구역(`answer-results`): 조건 요약·본문·카드·출처를 한 section에 배치한다. 요소 간격은 12px이며 카드 자체의 기존 간격·높이는 유지한다.
- 질문 구역(`answer-question`): 질문 문장과 답변 칩만 모은 별도 section이다. 배경 #fafafa, 라운드 16px, 패딩 16px, 위 여백 24px, 내부 간격 12px이다. 질문은 본문과 같은 16px/굵기 700이다.
- 답변 칩은 검정 1px 테두리·흰 배경·알약 모양·높이 40px 이상이다. 누르면 배경/크기가 반응한다. 상관없어요는 연한 테두리·투명 배경·오른쪽 정렬이다. 종류 타일(52px)/지역 전체 폭 버튼(48px)/위치 연결 검정 주 버튼은 기존 형태를 유지한다.
- 이어서 구역(`answer-followup`): 위 여백 24px과 얇은 구분선 아래 라벨·전체 폭 질문 행을 배치한다. 질문 구역이 있으면 최대 2행, 더 연한 채움과 #666 글자로 우선순위를 낮춘다. 클릭 기능은 유지한다.
- 작은 회색 테두리 행동 칩은 최하단이다. 복사/재생성은 기존대로 질문·답변 칩 뒤, 이어서 구역 앞에 남는다.
- 이전 질문/칩/연관 질문은 삭제하지 않고 다음 입력 시 비활성 이력으로 유지한다. answer_plan에 없는 블록은 렌더하지 않는다.

## 맥락과 검증

별도 AI 호출을 추가하지 않고 기존 분석/답변 생성 요청에 맥락과 규칙을 전달한다. 기존 결정적 빠른 경로는 맥락형 템플릿을 사용한다.

입력 맥락은 현재 사용자 발화, intent, 확정 지역·음식·상황 슬롯, missing_slots, 현재 확인된 카드, 대기 질문, askedSlots, 이미 노출한 제안과 최근 2응답의 문형 이력이다. 답변 생성 시 확인된 검색 카드와 정책상 다음 질문을 함께 전달하며, 최종 선택은 실제 응답 카드·대기 질문으로 다시 검사한다.

`RELATED_AXES`에서 의도별 허용 축을 유지한다:

| 응답 의도 | 이어서 제안 축 |
| --- | --- |
| place_search/condition_change/followup | 지역·메인 음식·상황 변경, 실제 식당 상세, 카드 2곳 비교 |
| menu_trouble | 다른 메뉴 묶음·종류·식당/지역 탐색 |
| compare | 실제 카드 상세·다른 비교·지역/음식/상황 변경 |
| specific_place | 상세·지역/음식 변경·다른 곳·비교 |
| food_talk | 음식 이야기·해당 메인 탐색·종류/메뉴 변경 |
| service/general | 고정 FAQ·메뉴 고민 시작 |
| out_of_scope | 메뉴 고민 시작 |

- 사용자 말투 12~30자 한 문장, 다른 축, 메인 메뉴/지원 지역, 서비스 FAQ 제한, 기존 제안·사용자 질문 중복 검사를 유지한다.
- 대기 질문과 같은 슬롯은 제외한다. 예를 들어 동행 질문 대기 중에는 ‘회식으로 역삼에서…’처럼 다른 축이 섞여 있어도 동행 제안으로 겹치므로 버린다.
- 실제 카드에 있는 상호/서수의 자세히·상세 정보 질문을 허용했다. 확인된 이름·분류·주소가 있는 카드만 상세 제안에 사용한다.
- 지역×음식 변경은 기존 분류기 사전 검증과 결과 존재 사전 검색/캐시를 유지한다. 상세/비교는 이미 보여준 확인 카드가 결과 존재 근거다. 정보가 없는 제안을 임의로 채우지 않는다.
- 같은 의미의 제안은 세션 shownSuggestions로 계속 차단한다. 추가로 지역·메뉴·상호·음식 조사를 정규화한 문형을 최근 2응답에 저장한다. 두 응답에 모두 나온 문형은 세 번째 응답에서 모델/템플릿 여부와 무관하게 차단한다. 슬롯·카드 내용을 반영한 다른 표현을 검증하고, 남지 않으면 개수를 줄인다.
- 슬롯 질문이 있으면 서버와 UI 양쪽에서 최대 2개로 제한한다. 분류·슬롯·검색 정책 자체와 실제 AI 평가/키 설정은 바꾸지 않았다.

## 테스트

`node scripts/build-worker.mjs && node scripts/policy-smoke.mjs`

전체 모킹 회귀에 다음 검사를 추가했다:

- 결과/질문/이어서 section의 DOM 분리, 본문·카드·출처·질문·칩·도구·제안·행동 순서
- 알약 답변·전체 폭 제안 행·작은 행동 칩의 별도 클래스, 질문 영역 배경/글꼴/간격/눌림 효과
- 대기 응답에 3개를 강제로 주어도 렌더러는 2개만 표시하고 낮은 톤 클래스 적용
- 대기 슬롯과 혼합 축 제안 중복 차단, 실제 카드 상세 허용, 장소 응답 FAQ 미포함
- 서로 다른 슬롯을 넣은 3회 응답에서 같은 문형의 세 번째 노출 차단(모델 후보 포함)
- 기존 모델 요청에 맥락 입력 포함, 추가 AI 호출 없이 모킹으로 검사
- 기존 v126 추천 행 클릭/직접 입력 카드, v127 카드/비교/복사/아이콘 및 입력·게임 회귀
- 인라인 JavaScript 문법과 diff 공백 검사

실제 AI/네이버 호출·키 파일 확인·AI 평가는 실행하지 않았다. 인증 실패/504 로그는 실패 처리용 모킹이다. **360~390px 실제 브라우저 픽셀 렌더 확인은 미완료**이며 DOM/CSS 계약 검사를 실제 렌더로 표현하지 않는다.
