# v124 연관 질문과 메인 메뉴 기준

## 변경 동작

응답은 기존 본문·카드·출처·질문·답변 칩 뒤에 `이어서 물어볼 수 있어요`와 연관 질문을 보여줘요. 기존 행동 칩은 그 아래 최하단에 남아요. 빈 슬롯을 채우는 짧은 칩과 다음 탐색을 제안하는 문장 행은 다른 UI예요.

연관 질문은 전체 폭 button이고 배경 #f3f3f3, 라운드 14px, 패딩 16px, 최소 높이 52px, 행 간격 8px이에요. 문장은 15px/#222, 오른쪽은 원형 화살표예요. aria-label은 질문 문장이고 키보드 포커스 표시가 있어요. reduced-motion에서는 화살표 이동을 멈춰요.

행을 누르면 질문 문장이 그대로 사용자 말풍선에 들어가고 기존 일반 입력 경로를 타요. 이전 그룹은 지우지 않고 비활성으로 남겨요. 다음 사용자 입력 때도 이전 그룹을 비활성화하며, 저장된 대화를 다시 그릴 때도 선택 상태를 복원해요.

## answer_plan 허용 표

`related_questions`를 블록 목록에 추가하고 `RELATED_QUESTION_POLICY`로 허용을 명시했어요. 최종 plan에는 검증된 질문이 있을 때만 블록을 넣어요. 렌더러도 plan에 없는 그룹을 그리지 않아요.

| 의도·응답 | 연관 질문 | 우선 방향 |
| --- | --- | --- |
| place_search 식당 카드 | 허용 | 인접 지역·유사 메인·상황·다른 곳 |
| menu_trouble 메뉴 후보 | 허용 | 같은 종류의 다른 메뉴·다른 종류·식당 찾기 |
| followup/condition_change 카드 | 허용 | 다른 축 값·남은 축·상황 |
| compare | 허용 | 실제 카드 한 곳 상세·조건 변경·다른 비교 |
| specific_place | 허용 | 같은 지역 다른 곳·상세보기 이용 안내·조건 변경 |
| food_talk | 허용 | 해당 메인 식당·메인 음식 이야기 |
| service/general | 허용 | 고정 FAQ 질문·메뉴 고민 시작 |
| out_of_scope | 시작 제안만 | 메뉴 고민 시작 |
| 종류·지역 질문, 낮은 신뢰도 확인 | 비노출 | 기존 답변 칩만 |
| 사이드 요청의 메인 질문 | 비노출 | 메인 선택 칩만 |
| 검색 결과 0건 | 비노출 | 대안 칩만, 행동 칩도 제외 |
| 하드 리셋 | 비노출 | 기존 초기화 안내 |

메뉴 카드 응답에는 노출하지만, 메뉴를 누른 직후 지역 질문으로 이어지면 지역 질문의 비노출 규칙을 우선해요.

## 생성·검증

1. 기존 분석 JSON에 `related_questions`를 추가했어요. 검색 답변의 기존 모델 호출에도 같은 필드를 추가해요. 분석 후보를 먼저, 답변 모델 후보를 그다음 검사해요. 별도 제안 생성·제안별 AI 분류 호출을 늘리지 않았어요.
2. FAQ와 결정적인 빠른 경로는 추가 AI 호출 없이 템플릿을 써요. FAQ 본문은 계속 `service-faq.json`의 고정 답변만 사용해요. 지원 지역·현재 위치·상세보기 이용 방법 FAQ도 실제 코드에 맞춰 추가했어요.
3. 사용자 해요체 문장 12~30자, 한 문장, v119 금지어·음슴체·내부 표현 없음, 영업시간·평점·가격·웨이팅·분위기·주차 등 확인 불가 질문 없음, 지원 지역과 메인 메뉴라는 조건을 검사해요.
4. 각 후보를 운영 코드의 로컬 분류기와 축 우선 정책에 통과시켜요. 통과하지 않으면 버려요. 공통 허용은 place_search/condition_change/followup/compare/service예요. 요청의 의도별 구성표에서 명시한 메뉴 탐색·음식 이야기·식당 상세·시작 제안은 각각 menu_trouble/food_talk/specific_place도 용도에 한해 허용해요. 이 예외는 공통 5의도 목록과 상세 구성표의 상충을 상세 구성표에 맞춰 해결한 것이에요.
5. 같은 응답에서는 서로 다른 방향을 2~3개 골라요. 현재 동행 질문과 askedSlots에 충돌하는 동행 제안은 제외해요. 이미 확정한 지역·음식을 무작정 재질문하지 않고, 값을 명시한 변경만 제안해요.
6. 문장과 의미 키를 `state.shownSuggestions`에 저장해요. 지역 별칭, 메뉴 교체, 동행, 같은 카드 쌍 비교 등은 같은 의미 키로 중복을 막아요. 실제 사용자 질문 기록도 검사해요. 하드 리셋으로 슬롯을 비워도 같은 대화의 제안 이력은 유지해요.
7. 생성 실패·시간초과·잘못된 JSON·검증 탈락이면 인접 지역/유사 메인/서비스 템플릿을 같은 검증기에 통과시켜요. 세션이 길어 새롭고 안전한 두 질문을 확보하지 못하면 억지로 반복하지 않고 그룹을 생략해요. out_of_scope는 중복 없는 시작 제안 한 개도 허용해요. 기록은 최대 1,000개이며 한도에서는 새 그룹 생성을 중단해요.

## 메인 메뉴

- `main-dishes.js`의 명시적 `main_dish=true/false` 사전을 사용해요. 메인 사전은 55개, 실제 메뉴 후보 풀은 52개예요.
- 메뉴 생성 허용 목록, 폴백 후보, 종류별 메뉴, 음식 변경 대안, 연관 질문, 링크 분석 뒤 메뉴 카드까지 같은 메인 기준을 적용해요. 사이드·음료·술·디저트가 들어간 후보와 부적절한 설명은 걸러요.
- 국밥·삼겹살·냉면·파스타·초밥·제육볶음 등 메인만 제안해요. 공기밥·계란찜·김치전·사이다·소주·아이스크림 등은 제안하지 않아요.
- `계란찜 먹고 싶어`처럼 사이드를 직접 말하면 검색 전에 `보통 어떤 메인과 같이 드세요?`와 메인 선택 칩을 보여줘요.
- `카페·디저트` 타일은 `카페 식사`로 바꾸고 샌드위치·샐러드·포케·토스트·베이글샌드위치·오믈렛으로 이어져요. 과거 카페·디저트 입력도 기존 카페 종류 경로로 받아요.
- 비교 뒤 상세 질문은 실제 직전 카드 이름을 사용해요. 숫자나 일반 명칭으로 끝나는 상호도 이름 참조로 처리하도록 보완했어요.

## 테스트 결과

- `node scripts/build-worker.mjs && node scripts/policy-smoke.mjs`: 전체 통과.
- 신규 `related-questions-smoke.mjs`: 10개 의도 노출, 종류/지역/사이드/0건 비노출, 2~3개와 서로 다른 축, 모델 후보·분석 후보 검증, 금지 질문·미지원 지역 제외, 잘못된 분류 후보 제외, askedSlots 충돌, 문장·의미 중복, 세션 이력, 생성 504·타이머 시간초과·잘못된 후보 형식 폴백, 실제 후속 라우팅, 메인 사전/풀/종류 목록, 사이드 6종 입력, 링크 메뉴 방어, 접근성 CSS를 확인했어요.
- 실제 인라인 렌더러 DOM 모킹: 칩→연관 질문→행동 칩 순서, button/aria-label/화살표, 클릭 문장의 전송, 선택 표시·이력 비활성·재클릭 방지, plan 밖 그룹 미렌더를 확인했어요. 실제 `routeQuestion→ask` 함수 경로도 테스트해요.
- 360/390px CSS/DOM 계약과 기존 전체 회귀 테스트, 인라인 JS 구문 검사, `git diff --check` 통과.
- 테스트 출력의 인증 실패·504는 의도적인 모킹 실패 사례예요. 실제 API 평가나 검색 API 호출을 하지 않았어요. 키 파일을 확인하거나 읽지 않았어요.
- **실제 브라우저 픽셀 렌더·360px 스크린샷·실기기 확인은 미완료**예요. CSS/DOM 확인을 실제 브라우저 확인으로 표현하지 않아요.
