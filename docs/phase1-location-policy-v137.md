# v137 — 맛집 추천 대화형 기능 1단계

## 이번 요청서가 우선하는 정책

- 위치만 필수다. 음식·예산·거리·인원·혼밥·목적·방문 시간은 제공된 값만 기억하며, 음식이 없어도 위치가 정해지면 바로 검색한다.
- `phase1-core.js`의 동일한 조건 변경 함수로 자연어 입력, 조건 칩, 플러그인/시트의 버튼 메시지를 처리한다. 기본 거리는 직선 1km다. 직접 지정한 양의 거리를 임의로 축소/확대하지 않는다.
- 새 추천/조건 변경/상세/비교/재조회/지도 의도를 `meta.phase1Intents`에 함께 기록한다. 비교+지도 등 복합 요청을 함께 안내하고, 대상이 불명확할 때만 확인한다.
- 1단계의 조건·검색 정책은 코드로 처리하며 OpenAI 호출을 추가하지 않았다. 예전 메뉴 필수·종류 질문·연관 질문 정책은 이 경로에서 사용하지 않는다. 이전 모델/링크 메뉴 조사 코드는 보존했으나 1단계 요청 경로에서 실행하지 않는다.

## 검색과 확인 가능한 정보

네이버 지역 검색에 `역 이름 + 음식` 또는 `역 이름 + 음식점`을 보낸다. 음식은 검색어에만 반영하며 카테고리는 음식점 계열 여부를 검사한다. 예전 상호/카테고리에 음식 이름이 문자 그대로 있어야 통과하던 조건과 주소 지역명 검사는 1단계에서 사용하지 않는다.

식당의 WGS84 좌표(mapx/mapy 변환)와 기준점으로 Haversine 직선거리를 계산한다. 좌표 없는 식당·범위 밖 식당·비음식점은 제외하고, 남은 검색 결과 중 가까운 순으로 최대 3곳을 표시한다. 카드에 `성수역에서 직선 400m`처럼 기준점과 거리 종류를 함께 표시한다. 도보·운전 거리나 특정 출구 기준 거리는 아니다.

대표 좌표는 수동 테이블이며 출구·현장 측량 정밀도는 검증하지 않았다. 테이블에 없는 역이나 동명/복수 대상은 임의의 역으로 치환하지 않고 확인한다. `강남구청역`을 `강남역`으로 잘못 잡지 않게 별칭 경계를 검사한다.

현재 위치는 브라우저의 권한 상태를 확인하고 좌표를 얻는다. 거부/실패 시 지역·역 선택/직접 입력으로 이어진다. 좌표를 얻었으나 역지오코딩이 실패해도 중단하지 않는다. 검색용 지역어가 없으면 가장 가까운 테이블 역을 검색어로 사용하되, 거리 계산과 카드 기준점은 **항상 실제 기기 좌표/현재 위치**다. 지원 테이블에서 먼 지역은 이 검색어 폴백으로 충분한 결과를 얻지 못할 수 있다.

네이버 지역 검색의 제한된 후보(현재 요청당 최대 5개) 중에서 검사한다. 범위 안의 모든 식당을 수집하거나 지역 전체에서 절대적으로 가장 가까운 식당을 보장하는 기능은 아니다.

## 선택 조건과 불확실성

- 결과 위 표시줄: 위치·거리, 제공한 방문 시간·음식·예산·동행/인원·목적·분위기·주차만 표시한다. 각 값은 클릭해 바꾸고 선택 조건은 해제할 수 있다. 위치 해제는 새 위치 선택으로 연결한다.
- 음식·위치를 바꾸면 지정한 축만 바꾼다. `500m 안으로`, `혼자 먹을 거야`, `내일 저녁에 갈 거야`도 다른 값은 유지한다.
- 가격·좌석·목적 적합성·주차·분위기·방문 시각 영업 여부는 현재 데이터로 검증하지 못한다. 조건은 기억하고 매장 확인이 필요하다고 알리되, 확인한 것처럼 필터/가산점을 만들지 않는다.
- 0건에는 현재 조건을 유지하고 2km 확대/음식 변경/예산 변경/지역 선택을 제안한다. 사용자가 선택하기 전 범위를 자동 확대하거나 다른 음식으로 채우지 않는다.
- 후속 버튼은 상태에 맞는 2~3개로 모으며 기존 연관 질문/상시 행동 칩과 중복 표시하지 않는다. 다시 추천은 같은 조건 재조회이며 새 식당 보장은 아니다. `다른 추천 N개` 기능은 추가하지 않았다.

## 시간대 예시

홈 배치는 유지하고 사용자 기기의 현지 시각으로 항상 3개를 표시한다. 05:00 아침 / 10:00 점심 / 14:00 오후 / 17:00 저녁 / 21:00 늦은 밤이며 00:00~04:59도 늦은 밤이다. 특정 지역을 임의로 넣지 않는다. 카페 검색은 허용하고 디저트/실시간 영업 중 제안은 이번 예시에서 제외했다. 후보 생성 실패·부족은 해당 시간대 기본 예시로 보완한다. 시간대 갱신은 홈 예시만 바꾸며 대화/선택 조건은 초기화하지 않는다. 사용자가 말한 방문 날짜·시간이 우선이다.

## 지도·상태·2단계 경계

`네이버지도 보기`는 도로명 주소 우선, 없으면 지번 **주소 단독**을 인코딩해 `https://map.naver.com/p/search/{주소}`로 연다. 상호·장소 ID·좌표 중심·출발지·길찾기를 붙이지 않는다. 주소가 없으면 비활성+주소 정보 없음이다. 건물/위치 결과가 나올 수 있고 식당 상세를 보장하지 않는다. 새 탭으로 열며 대화·조건·목록·선택 카드가 유지된다.

입력 전송→채팅 전환, 요청 중 상태, 20초 지연 안내, 45초 시간 초과, 네트워크/JSON 오류/0건/중단의 안내와 재시도를 유지했다. 버전 변경은 저장 후 재로드해 대화와 조건을 복원하며, 구버전 답변 본문/카드를 새 응답처럼 재사용하지 않는다.

2단계용 필드는 `imageUrl`, `menus`, `prices`, `recommenderName`, `recommendationReason`, `otherRecommendations`, `openingHours`다. null/빈 값만 두었으며 사진 수집·메뉴/가격 조회·추천인 표시·추가 추천 N개·영업시간 조회는 구현하지 않았다. 기존 추천인/이유 표시 값도 빈 값으로 내보낸다.

하단 고지: “메뉴·가격·영업시간은 변경될 수 있어요. 방문 전 식당 정보를 확인해 주세요.” FAQ도 새 거리·지도·데이터 범위에 맞게 수정했다.

## 미검증 / 제한

1. 성수 파스타의 실제 네이버 결과 복구와 실서비스 대화는 미검증이다. 빌드·모킹 smoke·배포 한정 요청에 따라 라이브 `/api/chat` 평가를 하지 않았다. 카테고리 누락 경로를 제거했고 `phase1_search` 로그에 원본 수·좌표 누락 수·범위 내 수·최근접 거리·질의를 남겨 실제 0건을 구분할 수 있다.
2. 주소 단독 네이버지도 URL을 읽기 도구로 열어보려 했으나 “URL is not accessible via this tool”이 반환됐다. 따라서 실제 지도 검색 화면/건물 결과/앱 전환은 미검증이다. URL 생성·인코딩·클릭 상태 유지 모킹만 통과했다.
3. 360~390px DOM/CSS 계약은 확인했지만 실제 브라우저 픽셀 렌더 및 모바일 위치 권한 팝업/기기 좌표 수신은 미검증이다. 대표 좌표의 현장 정확도도 미검증이다.
4. 현재 공급 데이터에 가격/좌석/주차/영업시간은 없어 해당 조건의 충족 여부나 순위 우위를 보장하지 않는다.
